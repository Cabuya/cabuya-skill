# Plan: Cabuya adoption — {{repo}}

## 1. Goal

Take this application to a **measured** Cabuya conformance level — target
**{{target_level}}** — by publishing a conforming `place` feed and manifest.

Measured is the operative word: the level this plan ends with is whatever the
validator reports, never a declaration. The plan contains exactly one decision
an agent cannot make — the PII gate — and it stops there until a human makes it.

## 3. Global Guidelines

- **Never invent data.** A field the app does not have is omitted (Extended) or
  reported missing (Core). There is no third option.
- **No person-level data, no contact values in the feed** — contact reaches
  users through `public_url`. The PII gate (its task below) is a human
  decision; on any validator PII finding, halt and ask.
- **Never claim a level the validator did not measure**, and never use the
  word *certified*.
- Every write to this repository is shown before it happens; no pull request
  is opened without asking.
- After each task: run its Validation, record the step in
  `.cabuya/adoption.json`, and check it off here.

## 5. Execution Rules for the Agent

- One task at a time; open the task file and follow it.
- Run every Validation command. A failing validation stops the plan — log it,
  do not mark the task done.
- `pii_gate` blocks on a human. There is no flag that skips it.
- Update the ledger after each task; `node {{pack_root}}/bin/check-ledger.mjs
  .cabuya/adoption.json` must pass after every write.
